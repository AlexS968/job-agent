# Следующее задание — JaCoCo и Sonar

Статус: задание после завершённой фазы 1; инструменты ещё не подключены.

## Результат

Проверяемое покрытие кода приложения и подготовленный анализ Sonar с Quality Gate. Работа отдельным инкрементом до бизнес-логики фазы 2.

## Реализация

1. Прочитать AGENTS.md, MASTER_PLAN_RU.md, PHASE_0.md и это задание. Сохранять существующие изменения. Работать локально в codex/quality-gates от подготовленного исходным чатом состояния. Не переключаться на старый main, теряя новые инструкции; проверить базу ветки.
2. Добавить совместимую с Java 21 стабильную версию jacoco-maven-plugin. Clean verify формирует HTML и XML отчёты, включая выполнение JobAgentApplication в отдельной JVM интеграционных тестов. Обычный prepare-agent для Failsafe не передаётся автоматически в ProcessBuilder: явно инструментировать дочернюю JVM, корректно собрать данные нескольких запусков и включить их в отчёт. После clean не использовать старые exec файлы. Не менять batch exit code и безопасную диагностику.
3. Проверить, что отчёт реально содержит покрытые строки/ветви приложения. Не исключать JobAgentApplication ради процента и не писать бессодержательные тесты. Согласовать обоснованные пороги до включения блокирующего coverage check; пока дать фактические измерения и предложение.
4. Подготовить Maven/SonarScanner и CI-анализ после verify с импортом JaCoCo XML. Размещение SonarQube Cloud — кандидат; не придумывать organization/project key и не создавать платные ресурсы. Сверить доступные условия и особенности PR analysis по официальной документации. Если аккаунт/ключи не предоставлены, подготовить конфигурацию через явно документированные GitHub Variables/Secrets и список точных действий пользователя.
5. Секрет SONAR_TOKEN только в GitHub Secrets; не читать и не публиковать его. Не передавать secrets недоверенным PR и не использовать pull_request_target для запуска непроверенного кода. Обычный build/test/coverage не зависит от Sonar-доступа. Отсутствие Sonar-конфигурации явно показывается как не настроено; не выдавать skip за успешный анализ.
6. Подготовить Quality Gate: ошибки, безопасность, maintainability, duplication и покрытие нового кода; фактические возможности/пороги документировать. Не считать gate или required GitHub check установленным без проверки. Изменение настроек аккаунта/репозитория пользователь выполняет с исходным чатом.
7. Обновить README проверенными командами, путями отчётов, условиями анализа и настройкой переменных/секретов. Соблюдать правила именования и слоёв. Не подключать бизнес-логику, AWS, брокер, MapStruct/Lombok без реального scope этого задания.

## Передача

Выполнить ./mvnw -B clean verify и git diff --check; проверить содержимое JaCoCo XML/HTML. Привести число тестов, покрытие и список включённых классов. Sonar-анализ и удалённый CI пометить не выполненными, если нет доступа/push.

Не делать commit, push, PR или merge. Исходный чат проводит ревью и может сделать commit; пользователь делает push и создаёт PR с подготовленными названием и описанием.

Короткий отчёт: результат, созданные/изменённые файлы, команды/проверки, измеренное покрытие, ограничения и действия пользователя для Sonar. Реальный Sonar Quality Gate проверяется после настройки аккаунта и публикации; не объявлять весь инкремент завершённым заранее.
