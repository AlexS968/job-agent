# Source architecture replacement and retirement register

Status: owner-agreed target direction, recorded 2026-11-17; cleanup remains proposed and undeployed. See the [system and AWS diagrams](TARGET_ARCHITECTURE.md). This is a cleanup contract, not an implementation or deployment claim. The target design has two independent vacancy inputs: permitted aggregator/alert feeds and verified employer career pages. An aggregator vacancy must remain usable when no readable employer career page exists. Employer discovery should accumulate a cross-channel employer registry; source-page monitoring, vacancy evaluation and owner feedback remain separate. Search covers Germany, Austria, Remote Europe and Remote Worldwide, with work-country eligibility evaluated from evidence rather than labels. Later AI work covers evidence-based matching, market analysis, and owner-approved CV/application drafts.

## Retirement rule

Each item below must either have a live, documented role in the approved design or be retired after its replacement is verified. Do not retain an unused parallel pipeline merely because it already exists. Do not delete or rewrite applied Flyway migrations, production history, source provenance, feedback, or already published notification identities. Use additive migrations and an explicit data transition. No code or Terraform removal is authorized by this document alone.

## Preserve and reuse

Keep the Greenhouse and Lever import adapters as two useful career-page readers; PostgreSQL/Flyway history; source observations and original URLs; transactional vacancy/outbox writes; SQS deduplication and retry contracts; candidate-role screening; evaluation and owner-feedback history; the protected Cognito/API Gateway/Lambda page; and the existing Fargate, Aurora, Secrets Manager, CloudWatch and SNS foundation. Refactor a component when it has a continuing role; delete only the code path made redundant by a verified replacement.

## Missing capabilities to add, not legacy to keep

1. Vacancy-producing adapters for approved channels. Candidate channels are LinkedIn email alerts (Java Gmail OAuth and old-pipeline cutover remain Phase 7 work), Adzuna (ongoing API price/terms not yet approved), Himalayas (public API), and Arbeitnow (Germany yield observed, Austria yield not established). Channel selection requires measured incremental useful vacancies and reviewed usage terms.
2. Canonical employer identities, channel aliases, official-domain evidence, career-page records and review of ambiguous associations. An employer may have no readable career page.
3. Due-time source monitoring with bounded work units, per-channel budgets, retries and measured capacity for hundreds or thousands of employers.
4. Cross-channel vacancy linkage and four geographic opportunity views with truthful remote work-country eligibility.
5. Bounded AI extraction/matching on changed, potentially relevant vacancies; later evidence-linked monthly market analysis and owner-approved base-CV updates, vacancy-tailored CVs and Bewerbungsschreiben. Provider and spend require separate approval before live use.

## Exit checks for each retirement PR

- Name the replaced path and demonstrate the new path with a non-ATS or aggregator-only vacancy and an employer career-page vacancy. Neither path may depend on the other being populated.
- Reconcile existing employers, source IDs, vacancy links, current evaluations, owner feedback and notification history before switching reads or deleting code.
- Inspect callers, scheduled modes, Terraform references and tests for the old path; remove unused code and configuration in the same replacement PR or record a specific, time-bound follow-up here.
- Verify bounded failures, duplicate inputs, retries and cross-channel identity conflicts at the affected boundaries. Run only the focused checks needed for the change; broader gates follow review and owner-approved resource use.
- Record a controlled production observation before claiming that a new channel or source-monitoring path works in AWS. A local test or API sample alone is not that observation.

## Open decisions before implementation

- Which channels become recurring inputs after measured incremental yield, terms and cost review; Adzuna's 25-call trial does not authorize a paid recurring plan.
- Which employer pages can be read under each provider's access rules; unsupported pages remain recorded without blocking aggregator vacancies.
- The first monitoring cadence, work-chunk size, concurrency and AWS cost ceiling, to be based on expected employer counts and measured task duration.
- The AI provider, pricing, monthly cap and private profile/document handling for later analysis and application drafts.
