# ADR 0003: Bounded search discovery pilot

Date: 2026-10-24. Status: approved for a limited pilot; provider quality and retention rights are not verified.

Tavily Search Basic is selected for Phase 3C.1. The [official Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search) documents `POST https://api.tavily.com/search`, explicit Basic depth, country/language preferences, a maximum result count and optional usage metadata. The [current credits page](https://docs.tavily.com/documentation/api-credits) lists 1,000 free credits per month without a card and one credit per Basic search. This is a pricing observation, not authorization to enable paid usage. PAYGO, payment methods and plans remain disabled. Brave Search API is a later fallback only; no Brave client or credential is part of this increment.

The entire pilot has a permanent local cap of 100 reserved outbound attempts, including retries, across restarts and concurrent processes. V6 stores one locked budget row and one operational attempt row per reservation. The reservation commits before HTTP; a crash or uncertain transport outcome remains charged against the local cap. A single invocation is limited to 12 attempts. The cap does not reset monthly and cannot be reset from the CLI. Provider-reported billed credits are recorded only when received, and may differ from locally reserved attempts. The owner must independently keep the provider account on its free plan; this application cannot verify billing settings.

The reservation service owns a short transaction containing both the guarded budget increment and attempt insertion; an insertion error rolls back both writes. The repository only executes SQL. The pilot rejects an ambient transaction before any reservation, and each reservation commits before its HTTP call. No HTTP runs inside a database transaction. Interruption while waiting to retry or awaiting HTTP cancels the entire invocation, preserving prior reservations and successful candidate URLs. The result marks cancellation and failure, and the batch exits nonzero. The interrupt flag is restored; no later query or retry is sent. A reservation made before a crash or cancellation is never refunded.

Search results remain transient and unverified. The pilot stores operational query-set version, query ordinal, reservation time, safe outcome, provider request ID and reported credits. It does not store snippets or full results. Returned candidate URLs exist only in the invocation output. The [platform terms](https://www.tavily.com/terms) do not establish a clear durable retention grant for complete outputs; confirm precise rights before designing durable result storage. Phase 3C.2 will verify official employer pages and ATS ownership with SSRF-safe fetching before activating sources. A search snippet, a live ATS endpoint or a country preference does not prove employer ownership or hiring eligibility.
