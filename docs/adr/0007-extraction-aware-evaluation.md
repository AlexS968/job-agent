# ADR 0007: Extraction-aware evaluation and shortlist

Date: 2026-10-30. Status: local implementation for review.

Policy `rules-extraction-v1` preserves the `rules-v1` decision, exclusion and ranking baseline. It reads extraction through the evaluation module's `ExtractionEvidenceService`, not directly from another module's repository. Evidence selection is exact: current vacancy revision and accepted source snapshot, `PRIMARY` work, provider `ANTHROPIC`, model `claude-haiku-5-5`, prompt `evidence-v3`, schema `schema-v3`, policy `pilot-v6`, status `SUCCEEDED` or `PARTIAL`, and at least one accepted claim. The unique extraction-work identity chooses at most one result. No timestamp or highest-ID fallback is used. Incompatible or stale results are unavailable, and evaluation never invokes a provider. The no-result basis is explicit `NONE`.

V13 adds extraction work identity, basis and bounded metadata to append-only evaluations. The unique evaluation key includes vacancy revision, profile ID/version/hash, evaluation policy and selected work ID plus basis. The work row carries the selected model and contract versions. Repeating the same evaluation inserts nothing; a newly available compatible work produces a new row, while the `NONE` row remains historical. A shortlist rereads the selected identity and only shows the matching current evaluation. The service owns each vacancy's transaction, including row lock, evidence selection, decision and insert. A failed insert rolls back that vacancy. The batch is explicit and bounded; no HTTP occurs in its transactions.

Source title, arrangement, exclusions and synthetic eligibility evidence retain precedence for decisions. Extracted title/family/seniority and arrangement are displayed as employer statements with quotations; they cannot override conflicting structured source fields or promote country eligibility. `COUNTRY_PERMISSION` is not independent work authorization. Accepted skills show exact value, requirement strength, quotation and section; alternatives remain one value. `UNCERTAIN` and `CONFLICTING` claims appear with warnings, never as definite requirements. Rejected claims are not rendered as facts; `PARTIAL` reports the rejection count and safe categories in stored metadata. A validated quotation proves source text was present, not that the employer statement is true or that the applicant has the skill.

Comparable accepted `SALARY_MIN`, `SALARY_CURRENCY` and `SALARY_PERIOD` facts can add a soft preference explanation. Missing/conflicting values, different currency or period remain unknown. Structured source salary takes precedence: when its comparison disagrees with extracted salary, both soft salary conclusions are withheld and disagreement is shown. No conversion or gross/net inference is made; a below-preference salary does not exclude. The private target is never printed. Suitable and needs-review groups, rank, preferred/reserve order, stable ID tie-break and limit remain as in ADR 0005. A needs-review-only shortlist is valid. This is an offline evidence-connection increment, not live quality validation, personal fit, independently verified country eligibility or event-driven evaluation.
