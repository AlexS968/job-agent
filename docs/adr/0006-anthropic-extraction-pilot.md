# ADR 0006: bounded Anthropic vacancy evidence pilot

Status: local implementation for review, 2026-10-28. No paid request or live pilot was run.

## Contract

Explicit extraction uses selected public vacancy fields only: title, location, description, source workplace type and salary. No private profile, CV, tools, browsing or credentials enter the prompt. Vacancy text is untrusted data. Claims carry fact, value, supplied source field, bounded supporting quote and uncertainty. Missing claims are UNKNOWN. A matching quote is evidence of a source statement, not legal permission or personal fit. Generic remote labels, EU references, office addresses and country mentions cannot confirm work-country permission. A positive permission claim is `STATED` only when its quote covers an entire source sentence matching one of the narrow unconditional employer-statement forms; negated, conditional, partial and ambiguous wording remains `UNCERTAIN`. This lexical check is deliberately conservative and is not unrestricted semantic validation or legal verification. Single-valued contradictory facts remain `CONFLICTING`. Quote matching uses NFC, case folding and whitespace collapse. `rules-v1` and shortlist behavior remain unchanged. Manual reference labels, not Sonnet output alone, will measure pilot quality.

Work identity contains vacancy ID, source snapshot ID, vacancy/source revision, provider/model and prompt/schema/policy versions. The exact selected input fields are retained as JSONB with the work item so quotations can be reviewed against the actual supplied snapshot after a vacancy row changes. Identical successful work is reused. Comparison uses Sonnet only after Haiku success on the same revision and input. Results stay separately reviewable; no automatic event or evaluation is created.

## Accounting and recovery

V10 stores the pilot budget, global in-flight claim, work and attempts. The owner approved a revised contract: USD 2 target spending for the entire pilot, USD 3 maximum authorized expenditure, at most 30 distinct primary Haiku revisions and 10 Sonnet comparisons, with no automatic top-up, fallback or expansion. USD 3 is authorization, not a billing guarantee. Live execution requires an API key, explicit command opt-in and same-day review of pinned pricing. No paid request has been run for this implementation.

Before HTTP, the application serializes the complete request (including system prompt, schema, source fields, output limit and thinking setting). It estimates input tokens as twice the UTF-8 request bytes plus 8,192 tokens for provider-injected schema/system overhead, then prices 2,048 output tokens including thinking. Request bytes are capped at 12,000; response bytes at 100,000; HTTP duration at 20 seconds. Haiku uses its higher long-context tier: $0.50/M input and $2.50/M output. Sonnet uses $2/M input and $10/M output. Cache writes, if reported despite no caching being requested, use the conservative one-hour 2x multiplier; reads use at least the base input price. All accounting uses integer micro-USD. These margins are conservative estimates, not verified upper bounds: Anthropic says token counting is approximate and structured output injects billable prompt material. An unexpectedly large bill remains possible after submission.

The reservation transaction locks the single budget row, requires no active claim or spending halt, and admits a proposed estimate only if accounted spending plus outstanding reservations remains within USD 2. It records one global active work/token and commits before HTTP; no database lock spans the request. At most 80 attempts and three per work item are permitted. Reported usage reconciles `input_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens` and `output_tokens`. Valid observed usage is recorded even when it exceeds the reservation or USD 3; any excess over the reservation durably halts new requests. Without valid usage, the full reservation remains, including refusals or uncertain transport outcomes. The accounted amount is known cost plus outstanding reservations; observed cost is reported usage only. Neither measure includes other account activity, taxes, adjustments or billing lag.

The durable global claim survives lease expiry, crash and uncertain acknowledgement; it cannot silently admit another request. An input exceeding the request byte limit is rejected before HTTP. A response exceeding the response byte limit is different: consumption is cancelled after submission, so provider completion and billing are unknown. It is recorded as `UNCERTAIN`, keeps the full reservation and global claim, and blocks other work. The source adapter and extraction gateway share a bounded HTTP body subscriber, while their callers retain their distinct failure classifications. A controlled recovery requires a 60-second age, operator confirmation that no provider request remains in flight and billing review. It releases the global slot but keeps the uncertain reservation, event identity and attempts. Replay is a separate explicit action and may bill again; exactly-once external execution is not claimed. A spending halt cannot be cleared by ordinary recovery. Claim-token fencing rejects stale completion. HTTP never holds a database transaction; ambient transactions are rejected. Failure-tracking errors are suppressed under the original request failure, and PostgreSQL outage can prevent tracking. Pre-interrupted work stops before reservation. Cancellation after reservation but before submission retains the full reservation; the gateway checks cancellation immediately before submission. Once submitted, cancellation can race with billing. The owner should review provider billing and available workspace monthly spend controls separately; no exact per-pilot provider hard cap has been verified or configured.
